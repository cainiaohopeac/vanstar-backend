# 标注平台统计分析模块 需求方案

> 版本：v1.1　范围：后端统计接口 + 前端统计页面　依赖：`ruoyi-label` 现有工作流/条目/标注模型

## 1. 背景与目标

现有平台已有「首页看板」（项目/资产/作业总量、待办、项目进度、团队产能），但缺少**以人和时间为轴的产能分析**：谁标了多少、每天标了多少、有效率多少、质量如何。管理者只能靠作业列表人工汇总。

本模块目标：

1. **产能可视化**：成员维度的条目/标签/帧产出，支持按节点（标注、一审、二审）、团队、时间范围收敛；
2. **趋势可视化**：成员 × 日期矩阵，识别产能波动与人员空转；
3. **效率可量化**：有效工时、单条耗时、每小时产出；
4. **质量可量化**：一次通过率、驳回率、返修次数（业内在产能之外必看的第二组指标）；
5. 页面形态对齐主流平台（截图即典型布局）：**顶部两个全局筛选 + 若干可全屏/可导出的图表卡片**。

不在本期范围：按项目核算成本/结算单价、目标与 KPI 达成、异常行为自动告警、跨平台数据对比。

## 2. 业内参考与取舍

| 平台 | 关键做法 | 本方案取舍 |
| --- | --- | --- |
| Label Studio | 以「项目 + 标注者 + 时间」聚合，提供 Labeling Efficiency / Annotator Performance 报表 | 采纳：成员 × 日期矩阵作为主视图 |
| Labelbox | 三层体系：Throughput（量）/ Quality（一次通过率、共识度）/ Cost（工时与单价） | 采纳前两层；成本留二期 |
| CVAT | 按 Job 统计已标注帧、已审核帧，区分「有标注帧 / 空帧」 | 采纳：帧工作量拆有标签/无标签 |
| Scale / 国内众包平台 | 计件 + 工时双口径，工时靠前端心跳采集，超时/挂机剔除 | 采纳：心跳采集 + 领取-完成时间差兜底 |
| doccano | 任务类型维度的简单计数（文档数/实体数） | 采纳：标签（实体/对象）计数 |

结论：**指标三层（产能 / 效率 / 质量）+ 三个筛选（节点 / 团队 / 时间）+ 卡片矩阵化**，与截图一致，不引入新概念。

## 3. 页面信息架构

```
统计分析
├─ 全局筛选：[节点选择 ▾] [团队选择 ▾] [时间范围 ▾]（可选：项目/任务/成员）
├─ 概览条（建议新增）：完成条目 / 标签数 / 处理帧数 / 参与人数 / 有效工时 / 一次通过率
├─ 第一屏：标注成员条目工作量（柱状）｜标注成员标签工作量（柱状）
├─ 第二屏：标注成员帧工作量（表格：有标签帧 / 无标签帧 / 合计）
│           标注成员每日标注条目数（成员 × 日期）
├─ 第三屏：标注成员每日标注帧数｜标注成员每日标注标签数
└─ 第四屏：标注成员工时分析（成员 × 日期，小时）
```

每个卡片统一具备（截图右上角图标）：**全屏、导出 CSV（服务端提供数据，前端转 CSV）、指标说明 ⓘ、刷新**；无数据时展示统一空态。

筛选规则：

- **节点选择**：来自各项目工作流节点（`label_workflow_node`）按 `node_key` 去重；默认选中 `node_type='label'` 的节点。**条目数 / 质量 / 工时** 按所选节点计（选审核节点时成员 = 审核人）；但 **标签数 / 帧数（产出类指标）始终归属标注节点**（`node_type='label'`），不受节点筛选影响，避免同一批标注对象在审核节点下被重复计入。
- **团队选择**：`label_team` 列表；命中规则 = 任务团队 或 项目主团队 或 项目关联团队（`label_project_team`）任一。
- **时间范围**：默认近 7 天（含今天），跨度上限 92 天；矩阵列按自然日连续补齐，缺失补 0。

## 4. 指标口径（核心）

| 指标 | 口径 | 数据来源 |
| --- | --- | --- |
| 完成条目数 | 指定节点下 `status='done'` 的条目数，按 `done_time` 归日；同一条目同一节点只计 1 次（返修不重复计） | `label_entry_node` |
| 处理中/跳过/放弃 | 当前状态计数，按 `update_time` 落范围，仅列表辅助展示，不进图表主值 | `label_entry_node` |
| 标签数 | 标注节点（`node_type='label'`）下完成条目覆盖的资产下的未删除标注对象数；**始终按标注节点口径，不受审核节点筛选影响** | 条目 → 资产 → 标注 → 对象 |
| 帧数（合计） | 标注节点覆盖的统计单元数；图片/文本项目 = 资产，序列项目 = 帧（`COALESCE(frame_id, asset_id)`）；**与标签数一致，按标注节点口径** | 同上 |
| 有标签帧 | 单元内至少 1 个标注对象 | 同上 |
| 无标签帧 | 单元存在标注记录但对象数为 0（负样本/空标注） | 同上 |
| 平均单条耗时 | `AVG(done_time - claim_time)`，仅统计两者都存在的记录 | `label_entry_node` |
| 有效工时 | 优先取心跳累计秒数；无心跳时回退 `Σ MIN(done_time - claim_time, 30min)` 并标记「估算」 | `label_work_session` / `label_entry_node` |
| 一次通过率 | 审核通过且 `reject_count=0` 的条目 / 已审核条目（`review_status ∈ passed,rejected,re_rejected`），仅统计 `node_type='label'` | `label_entry_node` + `label_data_entry` |
| 驳回率 | 已驳回条目 / 已审核条目 | 同上 |
| 返修次数 | `SUM(reject_count)` | `label_data_entry` |
| 人均产能 | 完成条目数 / 参与人数 | 聚合计算 |

口径约束（需在页面 ⓘ 中明示）：

1. **产量按「完成」计**：领取未完成、跳过、放弃都不计产量，只在列表辅助列展示；
2. **返修不重复计产量**：`label_entry_node` 一条目一节点仅一行，最终完成计 1 次，防止反复提交刷量；
3. **标签/帧产出只归属标注节点**：标签数、帧数是「标注动作」的产物，无论筛选选中哪个节点（含审核节点或未指定），均按 `node_type='label'` 的完成条目统计；避免在审核节点下把同一批标注对象重复计入，保证成员标签/帧工作量稳定可比；
4. **空标注算工作量**：有记录无对象计为「无标签帧」，鼓励做负样本，避免只挑有目标的帧标；
5. **工时低估可接受**：心跳口径依赖前端配合，缺失时回退估算（单条 30 分钟封顶），页面标记「估算」。

## 5. 卡片需求明细

| 卡片 | 形态 | 说明 |
| --- | --- | --- |
| 标注成员条目工作量 | 横向柱状图，X=成员，Y=条目数，悬浮显示处理中/跳过/放弃 | 按完成条目数降序，默认取前 50 名，支持"查看全部" |
| 标注成员标签工作量 | 横向柱状图，Y=标签数，悬浮显示"帧均标签数" | 用于识别"高产但只标框"或"细标多标签"的成员 |
| 标注成员帧工作量 | 表格：成员 / 有标签帧 / 无标签帧 / 合计 | 合计列可排序；导出 CSV |
| 每日标注条目数 | 矩阵：行=成员，列=日期，格=条数，末列合计，末行日合计 | 首列为成员，支持行排序与高亮 0 值 |
| 每日标注帧数 | 同上，单位帧 | — |
| 每日标注标签数 | 同上，单位个 | — |
| 工时分析 | 矩阵：行=成员，列=日期，格=小时（2 位小数），附加效率列 | 行尾展示"总工时 / 完成条目 / 单条耗时 / 每小时条目"；估算行加「估」角标 |
| 概览条（新增） | 6 个数字卡 | 完成条目、标签数、处理帧数、参与人数、有效工时、一次通过率 |
| 质量维度（新增，建议同页 Tab） | 表格：成员 / 已审核 / 一次通过率 / 驳回率 / 返修次数 | 与产能同筛选，帮助定位"快但差"的成员 |

## 6. 工时采集规则

1. 前端工作台在**页面可见且 5 分钟内有交互**时，每 60s 调一次 `POST /stats/work-session/heartbeat`，`seconds=60`；
2. 标签页隐藏（`visibilitychange`）、窗口失焦超 5 分钟、无操作超 5 分钟 → 停止上报；
3. 服务端按 `(user_id, task_id, node_key, work_date)` 唯一累加，单次秒数收敛到 1~600；
4. 当日无心跳记录时，统计页回退「领取-完成时间差」估算，单条封顶 30 分钟，并在行上标记估算；
5. 工时只用于效率分析，不直接用于结算（结算需二期引入审批与修正）。

## 7. 权限与数据范围

- 与管理看板一致：超管/项目负责人/团队负责人可看全量；普通成员默认只看自己（前端默认带 `memberIds=[当前用户]`，后端支持该过滤）。
- 团队筛选天然收敛数据范围；未选团队时不越权限制，依赖菜单权限（`sys_menu` 中「统计分析」）控制入口。
- 导出能力沿用现有权限体系，不建议开放全平台明细导出给普通成员。

## 9. 数据与性能

新增表 `label_work_session`（工时心跳），索引脚本见 `script/sql/label_stats_upgrade.sql`：

- `label_entry_node(operator_id, done_time)`：成员产能按完成时间归日；
- `label_entry_node(task_id, node_key, done_time)`：节点维度收敛；
- `label_annotation(asset_id, deleted)`：条目 → 资产 → 标注反查；
- `label_data_entry(task_id, label_status)`：质量统计范围收敛。

性能策略：

1. 单次查询跨度上限 92 天，`limit` 上限 200，避免全表扫描；
2. 前端各卡片独立请求、独立 loading，互不阻塞；
3. 数据量上到千万级标注对象后，改为**日粒度预聚合表** `label_stats_daily`（由提交/审核事件写入），统计接口只读预聚合；
4. 预聚合前若出现慢查询，可对近 30 天结果做 5 分钟本地缓存（当前未启用，避免统计数据不一致）。

## 10. 二期演进

1. **预聚合**：`label_stats_daily`（日期+成员+任务+节点+条目/帧/标签/工时），支持年度报表；
2. **成本与结算**：条目单价、工时单价、人天成本，输出结算单；
3. **目标与达成**：成员/团队日目标、周目标，达成率与排名；
4. **异常检测**：单条耗时异常（过快/过慢）、空标注率异常、批量相同标注；
5. **导出与订阅**：周报 CSV/Excel 邮件订阅，管理层看板大屏；
6. **文本标注适配**：文本项目无「帧」概念，帧工作量列自动替换为「文档数/段落数」，指标结构不变。

## 11. 变更记录

### v1.1（2026-10-28）
- **产出类指标归属修正**：标签数、帧数（成员标签/帧工作量、每日标签/帧矩阵、概览的标签产出/处理帧数）统一按 **标注节点**（`node_type='label'`）统计。
  - 原因：标签/帧是「标注动作」的产物，原先在选中审核节点时会按该条目（同一批标注对象）统计，导致 `review_1` 与 `label` 的标签产出相等、且审核节点下把标注产出当审核产出展示，语义混淆。
  - 行为：无论筛选选中哪个节点（含审核节点或未指定），产出口径都回落到标注节点；仅「完成条目 / 质量 / 工时」按所选节点计。保证成员标签/帧工作量稳定可比、不重复计入。
  - 实现：`StatsMapper.xml` 新增 `outputScope`（含 `labelOnly` 分支），`StatsServiceImpl.labelOnly(q)` 判定（未指定节点或选中审核类节点时为 true）；`StatsMapper.java` 接口新增 `labelOnly` 参数；已后端重启生效。
- **前端日期范围校验**：`stats.vue` 新增 `MAX_RANGE_DAYS = 92` 与 `validateRange()`，查询前校验跨度，超过 92 天时 `ElMessage.warning` 提示并阻止请求，日期选择器旁增加「最多 92 天」提示图标。
